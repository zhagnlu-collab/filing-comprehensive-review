# 修订后续核与回归检查

> 续核不是重新开始一轮复核，而是以原问题清单、原证据和原版本为基线，逐条检查修订是否闭环，同时确认没有引入新的错误。

## 一、输入

开始续核前必须具备：

- 上一轮内部 `findings.jsonl`（如可获取则直接复用；若只有已交付 Excel 或 Word，先据问题及证据重建内部记录，不要求用户额外提供 JSONL）；
- 上一轮问题清单或 Word 批注版；
- 上一轮文件 SHA-256；
- 修订后文件及其版本说明；
- 项目组的修订说明或逐条回复；
- 本次数据截止日和复核范围。

若原问题清单不存在，只能按新初核处理，不能假装完成了逐条闭环。

## 二、问题状态

每个原 finding 使用以下状态：

| 状态 | 含义 |
|---|---|
| `FIXED` | 已按建议或经确认的替代方案修复 |
| `PARTIAL` | 部分位置已修复，仍有残留或连带位置未改 |
| `NOT_FIXED` | 未修复或修订无效 |
| `NOT_APPLICABLE` | 经核验原问题不适用或已无该披露 |
| `REGRESSION` | 修复引入新的错误、口径变化或其它位置不一致 |
| `OPEN` | 尚未检查或等待补充 |

状态必须基于修订后原文和证据，不得仅依据项目组回复。

## 三、逐条闭环表

输出至少包含：

`原 finding ID | 原影响等级 | 原证据状态 | 原位置 | 原问题摘要 | 修订动作 | 修订后位置/原文 | 证据 | 闭环状态 | 回归检查 | 未决事项`

示例：

```json
{
  "finding_id": "FND-0001",
  "previous_impact": "A",
  "previous_status": "CONFIRMED",
  "review_status": "FIXED",
  "new_location": "问题九/（三）/第二段",
  "new_excerpt": "归母净利润为 21,008.43 万元",
  "evidence_ids": ["EVD-0011"],
  "regression_check": "PASS",
  "note": "已同步报告书与问题回复"
}
```

## 四、旧值、新值和连带位置

对每个修订点检查：

1. **旧值清零**：原错误数字、术语、名称、日期、单位和引用是否仍残留；
2. **新值同步**：新值是否出现在所有应当一致的文件、章节、表格和附注；
3. **变动列同步**：新增期间或新列后，余额变动、同比、环比和完成率是否重新计算；
4. **跨文件联动**：主文件更新后，对照文件、摘要、目录、图表和风险因素是否全部更新；
5. **口径同步**：修订后是否改变主体、期间、合并/母公司、实际/预测或单位口径；
6. **表述同步**：正文、表头、表注、图例和结论是否一致。

旧值检测不能只做简单全文替换。应同时检查：

- 数值的元/万元等价形式；
- 千分位、全角半角、括号和负号差异；
- 公司全称、简称和曾用名；
- 法规名称、文号、案号和评估机构名称；
- 同一数值在正文、表格、图片说明和附注中的不同写法。

## 五、回归检查

每次修订至少检查：

- 修订是否改变原意的其他部分；
- 修复一个位置是否导致另一位置不一致；
- 是否新增未定义简称或失效引用；
- 是否引入新的空白字段、模板残留或修订痕迹；
- 是否删除了必要的风险提示或限定语；
- 是否把错误口径扩散到其它章节；
- 是否出现旧值与新值并存。

回归检查结果使用：

- `PASS`：未发现新增问题；
- `FAIL`：发现新问题，生成新 finding；
- `UNVERIFIABLE`：缺少必要证据，无法判断。

## 六、续核输出

续核同样仅交付 Excel 问题清单、Word 批注版和 HTML 文件：

1. Excel：在同一工作簿内纳入原问题闭环、新增问题、旧值清零、新值同步、回归检查及未决事项。
2. Word：在修订后原件副本上锚定仍需处理及新增的问题，保留既有批注和修订。
3. HTML：展示续核结论、修复统计、关键依据、覆盖情况、限制及元审计结果。

更新后的 `manifest.json`、`findings.jsonl` 及证据台账继续保存在内部工作目录并用于校验，不单独交付；上述闭环表和检查表不再生成额外交付文件。

统计口径：

- 上一轮共 X 个问题；
- 已修复 Y；
- 部分修复 Z；
- 未修复 W；
- 不适用 N；
- 新增回归 R；
- 仍待项目组或专业人士决策 M。

## 七、门禁

以下任一未满足，不得将续核结论写成"问题已全部关闭"：

- 原 finding 未逐条核对；
- 只有项目组口头回复，没有修订后原文和证据；
- 旧值仍有残留但未说明；
- 新值只在一处更新，其他关联文件未同步；
- 回归检查发现新问题未列入清单；
- 原 A 级问题修订后未做元审计；
- `manifest.json` 未更新版本、哈希和截止日。
