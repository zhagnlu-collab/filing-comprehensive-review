# 重组申报文件常见错误及检查方法

> 基于监管问询案例、投行实战经验及历史重组项目实测整理的常见错误类型（文中项目名称为示例，仅说明方法，不得当作当前任务事实）。**按错误模式分类，每类给检查方法。**

## 一、数据不一致类（最高频）

### 1.1 同一指标多处披露不一致

**形态**：同一财务指标（营业收入/净利润/毛利率/应收账款）在正文、表格、图表、不同章节中出现 ≥2 处，数值不一致。

**检查方法**：
- 构建（主体, 指标, 期间）→ [(文件, 位置, 数值)] 索引，同一键出现多处但数值不同即候选；
- **≥3 处时三处两两对碰**（gotcha #5），不能只比碰到的两处；
- 主体归属铁律：先确认"比的是同一个主体"（合并 vs 单体、母公司 vs 子公司）。

**实测案例**：东实李尔 2026H1 归母净利润在 M 表 31/表 79/C6 表 8/C6 表 11 四处出现，C6 表 8 与表 11 不一致。

### 1.2 跨文件数据不同步（加期旧值残留）

**形态**：主文件已更新为审定值，其他文件（问题回复/重组报告书/备考报表）仍停留旧值或空值。

**检查方法**：
- 把"新值"和"旧值"分别 grep 所有文件全文，找出旧值残留位置；
- 联动值检查：归母净利润变了 → 投资收益（×50%）是否同步？合计贡献投资收益是否同步？
- 变动识别：楷体加粗 + 上期 diff 双重识别，追溯每个变动点在其他文件是否同步。

**实测案例**：东实李尔 2026H1 归母 14,455.51（M）vs 14,559.75（C6 表 8/C10 表 232 联动值 7,279.88）。

### 1.3 合计≠分项和（表格算术错误）

**形态**：表格"合计"行与明细行之和不一致，或"小计"行与分组明细之和不一致。

**检查方法**：
- 批量验算含"合计/小计/总计"行的表格；
- **四道误报关卡**：合并单元格假错位 / 分类小计 / 两层合计 / 加减结构，逐项回原始单元格精确核查后才能定性；
- 真实差异判定：无合并单元格、无分类小计、无中间合计、无加减结构，且偏差>0.05；
- **合计≠分项和时不要直接判"尾差"收口**：先看这个"合计"是否本应等于同小节其他载体披露的总额（如注册资本、出资总额、股本总额），差额是否等于某笔已知增资/减资/股权变动金额。若差额可被一笔真实变动解释，则问题定性从"尾差"升级为"口径/期间不一致"或"漏披露主体"——见 §1.7。

**实测案例**：坏账准备合计 3,631.38 ≠ 分项和 3,623.15（差 8.23 万），应收账款合计与分项和一致（排除四舍五入）。

### 1.4 合计行横向错位

**形态**：合计行 C2 存首年值、C3 存次年值，整体右移一列（或左移）。

**检查方法**：
- 合计行 C(ci) 披露值 ≈ 明细和 C(ci±1) → 错位嫌疑；
- 上期版本同样错位 → 本期沿用，非本次新增。

**实测案例**：东实李尔历史收入表 36/37 合计行整体右移一列（上期沿用）。

### 1.5 跨载体不一致（表 vs 图 vs 注释 vs 正文）

**形态**：同一事实（股权比例、交易对价、股东名称、注册资本、控制关系）在**正文段落／表格／图／表下注释／目录**五类载体之间不一致。最典型两种：
- **表已换版、图未同步**：正文表已更新为本期口径，结构图仍是上一版（图形是"冻结"的旧数据，改表时没人改图）；
- **图／表／注释三方主体名称不一致**：比例相同但主体名不同（图载旧名、表载新名，或图载简称、表载全称）。

**检查方法**：
- 按文档顺序**同时**提取段落文本、表格、图片（`kind` 需含 `image`），对每个"主体—比例—名称"三元组建立（载体, 位置, 值）索引；
- **图形载体必须实际提取并逐张识读**（含 DrawingML `a:blip` 与 VML `v:imagedata`），不得因"解析不到文本层"而默认排除或整体标记 `NOT_IN_SCOPE`；
- 交叉比对矩阵：行=事实，列=载体，格=`COVERED/PARTIAL/NOT_RUN/NOT_IN_SCOPE`；
- 发现不一致时**不得静默择一**：先判断哪个载体是现行口径（看该载体是否在修订留痕中被保留/删除），再定性；
- 修订稿要专门检查 `w:delText`（被删旧文）——**图与"已删除的旧表"逐字吻合，是"表已换版、图未同步"的铁证**。

**实测案例**：某重组预案交易对方章，蜂巢能源结构图载"瑞茂 37.56%／讯奇 21.14%"，正文表载"瑞茂 38.18%／讯奇 2.10%"；图内数据与文档中**已被删除**的旧表完全一致 → 判定为表已换版、图未同步。

### 1.6 图内遗漏主体（该层合计不足 100%）

**形态**：结构图/关系图把某层股东列全，但漏画一名（或多名）股东，导致图内该层比例合计 ≠ 100%（如 99.42%、99.01%）。

**检查方法**：
- **逐层合计自检**：对结构图每一层（每个方框内的并列股东）把图内比例相加，必须 = 100.00%（±0.01 四舍五入）；不足即说明图内漏主体，超出即说明重复或比例抄错；
- 用同节表格的股东名册反查图内漏掉的是谁；
- 表侧同步做一次逐层合计（表内合计行 ≠ 100.00% 同样说明漏主体或口径混用）。

**实测案例**：某预案中蜂巢能源图漏"韩雪娟 0.5882%"（层合计 99.42%）、贵阳蜂巢图"魏建军 69.00%"（工商登记 69.99%，层合计 99.01%）、点石贰号图漏"王琴 17.5431%"、合庐一号图漏"谢中平 99.00%"。

### 1.7 出资／股权结构表"合计"≠同节注册资本

**形态**：出资结构表（股东名册）"合计"行金额与**同一小节**"基本情况表"所载注册资本（或出资总额、股本总额）不一致。

**检查方法**：
- 出资／股权结构表的"合计"必须与同一小节"基本情况表"的注册资本（或出资总额）对碰，**不得降为尾差**；
- 差额反查工商**变更记录**（`get_change_records`）：注册资本增减、股东进出、名称变更均可解释差额；差额能被一笔真实变动解释时，问题定性为"口径/期间不一致"或"漏披露主体"，而非算术尾差；
- 注意工具返回的"持股比例"可能按**认缴出资额合计**计算，与**注册资本**不同基数，比较前先统一基数；
- **方向不得假定**：不能因为"旧表合计=工商现值"就断定新表错、旧表对，必须确认现行表的期间口径应取增资前还是增资后，并以项目组/工商档案为准。

**实测案例**：某预案蜂巢能源出资结构表合计 334,637.42 万元 ≠ 同节注册资本 340,190.78 万元，差 5,553.36 万元，恰等于工商变更记录中 2026-07-06 的一次增资额；同时该表明细加总 334,637.47 与合计行 334,637.42 亦差 0.05 万元。

## 二、口径/分母不一致类

### 2.1 同一数字不同口径/分母

**形态**：同一指标，一处分母是"营业收入"、另一处是"主营业务收入"；一处是"合并口径"、另一处是"母公司口径"。

**检查方法**：
- 每个关键数字标五维（主体/期间/单位/口径/指标），五维全一致才可判冲突；
- 口径不一致即使数值相同也是问题（gotcha #1）。

### 2.2 率×基数≠金额

**形态**：占比×总额≠披露的分项金额；毛利率×收入≠毛利额。

**检查方法**：
- 复算：占比×总额应≈分项金额，毛利率×收入应≈毛利额；
- 只核"跨表一致"会漏掉这类错（gotcha #3）。

### 2.3 方向词 vs 数据

**形态**：文字说"增长/上升"、数据却是下降；上期"同比增长"的措辞照抄到本期但数据实为下降。

**检查方法**：
- 对加期变动段落，逐句检查方向词与数据方向是否一致；
- 模式：`从 X 增至 Y`（Y<X 即方向反转）、`同比增长 XX%`（实际为负）。

### 2.4 完成率/比率口径混用

**形态**：正文用"净利润"口径、表格用"归母净利润"口径；一处完成率=实现/预测、另一处=实现/预算。

**检查方法**：
- 底稿双口径验证：净利润口径 5,287.58/9,629.67=54.91%，归母口径 5,309.52/9,553.26=55.58%，各自正确但正文混用即问题。

## 三、加期特有错误类

### 3.1 加期漏更新

**形态**：报告期从"2024、2025"扩为"2024、2025、2026H1"后，应更新到最新报告期却未更新。

**检查方法**：
- 期数列检测：财务数据表列头含"2024/2025"但不含"2026" → 候选；
- 上期 diff：上期两期表述 vs 本期应三期却仍两期；
- 排除：评估口径/商誉/历史沿革/交易对方不更新。

### 3.2 加期旧值残留

**形态**：加期修订某数字后，其他文件联动值停在旧值。

**检查方法**：
- 新值/旧值/联动值分别 grep 所有文件；
- 联动值=归母×持股比例、合计=各主体之和。

### 3.3 表述疑误（期间/数量不匹配）

**形态**：「2020 年至 2023 年上半年」对应四个数值（23.05/21.73/22.98/20.66），期间与数量不匹配。

**检查方法**：
- 期间表述 vs 数值数量比对：N 个数值需要 N 个期间；
- 常见模式：「X 年至 Y 年上半年」+ 四个年度数值 → 应为「X 年至 Y 年」。

## 四、表述/文字错误类

### 4.1 尾差

**形态**：同一数值在不同位置尾数不一致（21,526.91 vs 21,526.90），底稿精确值 21,526.9045 应为 21,526.90。

**检查方法**：底稿精确值四舍五入后比对各处披露值。

### 4.2 合计行差 1

**形态**：研发立项/结题个数合计行较分项和少 1（33 vs 32）。

**检查方法**：整数计数类表格（个数/家数/人数）合计=分项和，不允许四舍五入。

### 4.3 文字与表格不一致

**形态**：正文"前五大客户合计占比 92%" vs 表格五项之和=91.5%。

**检查方法**：正文中的百分比 vs 表格对应分项之和复算。

## 五、外部可验证错误类

### 5.1 工商信息矛盾

**形态**：文件披露的法定代表人/注册资本/成立日期与工商登记不一致。

**检查方法**：企查查 MCP 核验（见 external-check.md §1）。

### 5.2 法规引用失效

**形态**：引用的法规已被修订/废止（如"根据《XX 法》第 X 条"但该条已修改）。

**检查方法**：qcc-legal-regulation 核验（见 external-check.md §2）。

### 5.3 案号引用虚假

**形态**：引用的裁判文书案号不存在。

**检查方法**：qcc-legal-case 核验（见 external-check.md §3）。

### 5.4 合规主张与司法记录矛盾

**形态**：文件主张"无重大违法违规"但存在行政处罚/裁判文书记录。

**检查方法**：qcc-legal-regulation + qcc-legal-case 反向查证（见 external-check.md §4）。

### 5.5 股权／合伙人结构转抄未回源

**形态**：交易对方章、标的公司股东层的股权结构（名称、比例、注册资本、控制关系）系从底稿或上一版文件转抄，未与工商登记核对，导致主体名称过时（已改名/已注销/已退出）、比例过时（未跟进增资）。

**检查方法**：企查查 MCP 回源（见 external-check.md「股权结构／合伙人结构专项」）：
- 逐层 `get_shareholder_info` 核名称与比例；
- **必查 `get_change_records`**：只有变更记录能确立名称沿革、比例变化、注册资本增减——这是判断"图上旧名 vs 表上新名"哪一个是现行口径的唯一依据；
- `get_company_registration_info` 核注册资本、成立日期、法定代表人；
- 比例基数校验：工具返回比例按认缴出资额合计计算，与注册资本口径不同，先统一基数再比。

**实测案例**：某预案招证冠智结构图载"宁波旭长朝""张旭"，正文表载"深圳旭腾创企业管理合伙企业（有限合伙）""范淑凤"，比例完全相同 → 图/表主体名称不一致。

## 六、检查优先级

| 优先级 | 错误类型 | 原因 |
|--------|---------|------|
| P0 | 跨文件数据不同步（加期旧值残留） | 监管问询必查，直接影响申报质量 |
| P0 | 合计行横向错位 | 硬伤，交易所看到必退 |
| P0 | 跨载体不一致（表 vs 图 vs 注释） | 硬伤，同一事实两套数，且图最易被漏查 |
| P1 | 同一指标多处不一致 | 硬伤，影响可信度 |
| P1 | 合计≠分项和（真实差异） | 硬伤 |
| P1 | 出资表合计≠同节注册资本 | 硬伤，直指漏主体或口径错 |
| P1 | 图内遗漏主体（层合计<100%） | 硬伤，图与表股东名册不符 |
| P2 | 口径/分母不一致 | 易误判为"一致"，需五维判定 |
| P2 | 加期漏更新 | 加期特有，影响完整性 |
| P2 | 股权/合伙人结构转抄未回源 | 需工商变更记录才能定性 |
| P3 | 方向词 vs 数据 | 加期特有，上期措辞照抄 |
| P3 | 表述疑误/尾差/差 1 | C 级，影响专业度 |
| P4 | 外部可验证错误（法规/案号/处罚） | 可选扩展，需 MCP 支持 |

## 七、与统一数据结构的衔接

所有错误模式命中后，不只写检查结论，还要生成结构化对象：

- 事实和数据点 → `CLM-`；
- 底稿、文件或外部来源 → `SRC-`；
- 支持、反驳或背景证据 → `EVD-`；
- 进入问题清单的异常 → `FND-`；
- 检查覆盖情况 → `COMPLETE/PARTIAL/NOT_RUN/UNVERIFIABLE/NOT_IN_SCOPE`。

**载体维度**：每条 `CLM-` 应带载体标识（正文段落／表格／图／注释／目录），跨载体比对即按"同键不同载体"成对生成；图形载体命中后须把提取出的图归档为 `EVD-`（含页码与图内数据），使结论可被用户在原件中 Ctrl+F/翻页定位。载体覆盖矩阵须随交付物一并给出。

脚本或模型命中先写 `CANDIDATE`；回原始载体、底稿或权威来源确认后再写 `CONFIRMED`。具体字段和校验规则见 `evidence-ledger.md` 与 `scripts/validate_review_artifacts.py`。
