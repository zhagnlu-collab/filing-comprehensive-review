# 来源评价与事实核验

> 吸收事实核查技能的证据纪律。目标是明确"来源支持什么、支持到什么程度、是否有反向证据、结论何时需要更新"，而不是用来源数量投票。

## 一、先拆主张

外部检索前先拆解 claim，并标明类型：

| 类型 | 示例 | 核验重点 |
|---|---|---|
| 数值主张 | 营收 20.74 亿元 | 数值、期间、口径、单位和来源 |
| 法规主张 | 根据某法第 X 条 | 原文、适用主体、生效和修订状态 |
| 业务事实 | 第一大客户为某某公司 | 合同、披露、工商、访谈或底稿 |
| 合规否定 | 报告期不存在重大违法违规 | 反向检索裁判、执行、处罚和监管记录 |
| 预测假设 | 2027 年销量增长 20% | 模型、依据、敏感性、是否已披露 |
| 前瞻陈述 | 项目投产后将提升产能 | 与计划、风险和假设是否一致 |
| 意见判断 | 本次交易具有协同效应 | 事实依据和推理链，不要求客观真假 |
| 不可证伪表述 | 行业前景广阔 | 提示表述风险，不强行外部证真 |

不要把所有句子都当同一种 claim。预测、意见和不可证伪表述不能与客观数字使用同一验证标准。

## 二、来源层级

| 层级 | 来源 | 默认用法 |
|---|---|---|
| `AUTHORITY` | 法律法规、监管规则、法院/政府官方记录、交易所正式公告 | 可直接作为权威依据 |
| `OFFICIAL` | 公司公告、年报、招股书、官网单篇披露、官方 IR | 用于公司事实和公开披露 |
| `PROFESSIONAL` | 审计、评估、法律、券商研究、行业协会 | 需确认主体、期间、方法和独立性 |
| `MEDIA` | 有编辑责任的财经媒体 | 用于发现线索，关键事实需回原始来源 |
| `OTHER` | 搜索摘要、聚合页、无来源转述 | 不作为单独证据 |

来源评价同时检查：

- 发布主体和作者；
- 发布日期、更新日期和访问日期；
- 原始出处和引用链；
- 是否为主要来源或二手转载；
- 与其它来源是否独立；
- 是否存在利益冲突；
- 是否受登录、付费、地区或反爬限制；
- 是否能定位到具体段落、页码或数据字段。

## 三、侧读和反向检索

对关键来源不只读当前页面，还要检查：

1. 发布主体是否有权发布该信息；
2. 同一事实是否有独立来源；
3. 是否存在相反证据、后续更正或撤回；
4. 是否存在同名主体、不同期间或不同口径；
5. 搜索摘要是否与原文一致；
6. 链接是否跳转到错误页面或首页。

关键否定性主张必须反向检索。例如"无重大诉讼""无处罚""不存在关联交易"不能只引用公司说明，还应查监管、裁判、执行、处罚和公开披露记录。

## 四、证据关系

每个来源对 claim 标记：

- `support`：直接支持；
- `refute`：与 claim 矛盾；
- `context`：补充口径或背景；
- `duplicate`：转载或非独立来源。

必须区分：

- **没有找到证据**：不是错误，只是无法核验；
- **找到相反证据**：可能构成 `CONFIRMED` 冲突或错误；
- **证据不足**：使用 `UNVERIFIABLE`；
- **来源互相矛盾**：保留双方，交项目组或专业人士决定。

禁止把"未检索到"写成"不存在"，也不能把"公司说明"自动等同于"客观事实"。

## 五、来源日期与数据截止日

每条外部 claim 记录：

- `claim_period`：主张覆盖的报告期或事实期间；
- `publish_date`：来源发布日期；
- `access_date`：实际访问日期；
- `data_cutoff`：本次复核的数据截止日。

规则：

- 来源发布日期晚于数据截止日时，应标记为后续信息，不得混入报告期结论；
- 使用"最新""目前""截至"等词时，必须相对数据截止日解释；
- 来源后续更新时保留原结论、原日期和更新记录；
- 不能用训练数据中的记忆替代当前来源。

## 六、横向独立验证

重要事实尽可能满足：

- 一个权威原始来源；或
- 两个互相独立的可靠来源；或
- 一个来源加项目底稿、合同或原始凭证。

以下不构成独立验证：

- 同一新闻稿的多家转载；
- 相互引用但没有原始来源的报道；
- 搜索摘要和原网页；
- 同一数据库的多个展示页面；
- 由待核文档自己提供的外部引用。

## 七、核验步骤

1. 拆解 claim 并标注类型；
2. 定义主体、期间、口径和所需来源层级；
3. 优先检索原始来源和官方单篇页面；
4. 记录来源、原文摘录、定位、日期和访问限制；
5. 进行侧读和反向检索；
6. 建立 evidence 关系，标记支持、反驳、背景或重复；
7. 形成 `CONFIRMED / CANDIDATE / UNVERIFIABLE` 结论；
8. 将来源和证据写入 `evidence-ledger.json`。

## 八、透明修订

外部来源更新或新证据出现时：

- 不删除原结论和原推理；
- 增加 `updated_at` 和变更说明；
- 明确哪些 finding 因此升级、降级或关闭；
- 若影响已交付版本，生成修订记录而不是静默覆盖；
- 对无法继续访问的来源标记 `access_limited`。

## 九、与本项目的结合

- 工商信息、法规、案号、合规反向查证、年报和同业核查的具体工具路径见 `external-check.md`；
- 来源和证据必须进入 `evidence-ledger.md` 规定的数据结构；
- 外部检索默认关闭，仅在用户明确确认后启用；
- 外部服务不可用时，记录降级渠道和未覆盖范围，不得用通用记忆补足。
