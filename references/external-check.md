# 外部取证与核查

> 一般外部核查默认不启用，仅在用户明确授权相应范围时执行。第 6 节上市公司定期报告取证专项已获用户授权：复核对象涉及上市公司信息且未提供对应定期报告时自动执行，无须再次确认。文中企业与工具名称均为历史项目示例；实际可用工具以工具发现结果为准。
>
> **优先级提示**：启用包含工商回源的一般外部核查时，**第 1 节"股权结构／合伙人结构专项"优先于其他各项**——申报文件中的股东/合伙人/出资比例/注册资本是从工商登记转抄的，是错误率最高、且最容易被"只做文件内部一致性"漏掉的一类数据。启用后不得只查法规和年报而跳过股权结构回源。

## 1. 主体工商信息核查

### 触发条件

主文件中出现企业名称（含"有限公司/股份/集团"后缀），且用户要求外部核查。

### 核查内容

| 字段 | 核查方式 |
|------|---------|
| 企业名称是否真实存在 | 工商核查工具按企业名检索 |
| 法定代表人 | 工商核查工具注册登记信息 |
| 注册资本 | 同上 |
| 成立日期 | 同上 |
| 经营范围 | 同上 |
| 股东结构 | 工商核查工具股东信息 |
| 实际控制人 | 工商核查工具实控人信息 |

### 主体归属铁律（强化）

每个企业用**自身名称**作查询 key，结论归于该主体。文档"控股股东/实控人"章节披露的工商字段，须以该控股股东企业名称为 key 查询并标注 `[控股股东口径]`，**禁止**直接与主文件主体混比出"工商矛盾"。跨主体混比 = 误报。

### 股权结构／合伙人结构专项（转抄类数据，必须回源）

交易对方、标的公司、合伙企业、持股平台的**股东/合伙人名单、出资比例、认缴出资额、注册资本、企业名称**属于**从工商登记转抄**的数据，抄录与口径错误率高，且申报文件中常以"出资结构表 + 产权控制关系结构图 + 表下注释"三种形式重复披露。核查要求：

1. **逐主体回源**：对每一个交易对方/股东/合伙人实体，调 `qcc-company__get_shareholder_info` 取一层股东/合伙人及持股比例、认缴出资额；
2. **必须同时调取变更记录**（`qcc-company__get_change_records`）。名称沿革、比例变化、注册资本增减**只有变更记录才能定性**——例如同一主体先后经历"更名 → 迁址异地并再次更名"，只查现状无法解释图中旧名与表中新名并存；
3. **必须取登记信息**（`qcc-company__get_company_registration_info`）核对注册资本、成立日期、法定代表人、经营范围、登记状态；
4. **一层比例逐字引用**，禁止相乘推断穿透比例；穿透/受益以 `get_actual_controller`／`get_beneficial_owners` 为准；
5. **比例基数须验证**：工具返回的"持股比例"以其认缴出资额合计为基数计算。若该基数与该主体登记的**注册资本**不一致（例如注册资本已增资而股东明细未同步），须作为口径冲突记录，不得直接采信任一方；
6. **核对方向**：文件披露 vs 工商登记逐项比对；不一致 → 标红并注明差异方向与差额，**不静默择一**。

### 工具发现（第 0 步）

先枚举当前环境实际可用的工商/法规核查工具（企查查、天眼查、元典等 MCP 或插件），以实际可用者为准；以下优先级仅在多个工具同时可用时参考：

1. `qcc-company`（企查查）
2. `tyc-mcp`（天眼查）
3. `qixinhuiyan-mcp`（启信慧眼）
4. WebSearch 降级（全部断开时，需用户确认）

### 降级清单（全部工具断开时，≥3 源含 ≥1 官方）

1. 国家企业信用信息公示系统 `gsxt.gov.cn`（官方：法代/注册资本/成立日期/登记状态/经营范围）
2. 天眼查免费公开页 `tianyancha.com/search?key=企业名`（工商快照，交叉验证）
3. 爱企查公开页 `aiqicha.baidu.com`（百度系，工商快照）
4. 企查查搜索页 `qcc.com/search?key=企业名`（无需登录可看基础工商）
5. 巨潮/公司官网年报（股东结构、实控人认定原文）
6. 信用中国 `creditchina.gov.cn`（行政处罚/失信/黑名单，反向印证主体状态）

### 结论分级

| 判定 | 含义 |
|------|------|
| 一致 | 工商信息与文件披露一致 |
| 不一致 | 工商信息与文件披露矛盾（标红） |
| 部分命中 | 部分源命中、部分未公开（写明已查 X 源，其中 Y 命中，Z 未公开） |
| 未公开 | 全部源均未公开（列明已穷尽渠道，不编造） |

## 2. 法规/法条引用核验

### 触发条件

主文件中出现「根据《XX法》第X条」「依据XX规定/办法」「按XX通知要求」等法规引用。

### 核查方式

首选**国家法律法规数据库**（`flk.npc.gov.cn`）核验法规现行有效性（是否修订/废止/失效）；商业库（北大法宝/威科）作辅助。已接入法规核验工具时：调 `qcc-legal-regulation__get_legal_citation_verify`，将含引用的原文整段传入（≤5万字），工具自动识别并回库校验每条法规/法条引用的真实性与时效性。

### 判定

- 命中且现行有效 → 通过
- 命中但已修订/废止 → 标红，附时效性说明
- 未命中 → 标注「存疑/未核验」，**禁止默认真实有效**

### 降级（法规核验工具断开时）

1. 国家法律法规数据库 `flk.npc.gov.cn`（官方，法条逐字时效性核验）
2. 北大法宝/威科/法规库官网（法条逐字时效性核验）
3. 信用中国（处罚法规）
4. WebSearch 搜索法条名称+修订状态

## 3. 裁判文书案号引用核验

### 触发条件

主文件中出现「（20XX）XX民初/执/刑初XX号」等案号引用。

### 核查方式

调 `qcc-legal-case__get_judicial_citation_verify`，将含案号的原文整段传入，工具自动识别并回库校验案号真实存在性。

### 判定

- 命中 → 溯源到标准案号+法院+审级+裁判日期
- 未命中 → 标注「存疑/未核验」，禁止默认真实

### 降级（qcc-legal-case 断开时）

1. 中国裁判文书网 `wenshu.court.gov.cn`（案号/文书）
2. 执行信息公开网 `zxgk.court.gov.cn`（被执行/失信）
3. 企查查搜索页案号检索 `qcc.com/search?key=案号`

## 4. 合规反向查证

### 触发条件

主文件主张「无重大违法违规」「无重大诉讼」「报告期内未受行政处罚」「合规经营」等否定性合规结论。

### 核查方式

1. 调 `qcc-legal-regulation`：检索主体相关行政许可/资质法规与处罚法规，查是否存在与"无违规"主张相悖的法规处罚记录。
2. 调 `qcc-legal-case`：`get_judicial_case_search` 以 `party=主体全称` 检索涉诉文书（含普通裁判文书、执行案件）。
3. **监管措施与纪律处分查询**：证监会官网（行政执法/行政监管措施）、沪深交易所官网监管信息公开/纪律处分栏目、证券期货市场失信记录查询平台，核查标的公司及控股股东、实控人、董监高是否被采取监管措施、纪律处分或行政处罚。
4. 发现与主张相悖的记录 → 标红「合规主张与司法/监管记录不符」，溯源到文书案号/法规名称+字段。

### 主体归属铁律同样适用

以该主体自身全称为查询 key，结论归于该主体；控股股东/实控人的涉诉记录不得直接套用于标的公司（须标注 `[控股股东口径]`）。

## 5. MCP 调用记录（mcp_calls.json）

每次外部 MCP 调用都按 `{target, tool, status}` 记入 `<输出目录>/mcp_calls.json` 的 `mcp_calls` 数组：

```json
{"target": "某标的公司", "tool": "qcc-company__get_company_registration_info", "status": "ok"}
{"target": "某合营企业", "tool": "qcc-legal-case__get_judicial_case_search", "status": "disconnected"}
```

status 取值：`ok`（已调已覆盖）、`failed`/`quota_exceeded`/`skipped`/`disconnected`（外部限制，仅记录不罚）、`missing`/`not_called`（覆盖缺口）。

## 6. 上市公司定期报告自动取证与核对（已授权专项）

### 触发与范围

如果作为复核对象的重组预案、重组草案等文件中含有上市公司相关信息，且用户未提供该上市公司对应的年度报告、半年度报告或季度报告，自行从巨潮资讯等官方披露来源联网下载，并以下载文件作为底稿核对复核对象。该专项不以正文是否明确引用某份报告为前提，也不等待用户另行提出“外部核查”。

按披露事项的主体、期间、时点和口径确定所需报告，仅补取缺失的相关文件；用户已提供合适版本时直接使用，不重复下载。该专项授权不自动扩展其他外部核查。

### 取证与核对方法

1. **明确匹配关系**：核对上市公司名称及证券代码，列出披露事项对应的报告期和时点。下载相应年度报告、半年度报告或季度报告的完整原始文件，不以摘要、搜索结果、终端数据或新闻转述代替。
2. **从官方渠道下载**：优先巨潮资讯网，亦可从上市地交易所或公司官网投资者关系页取得官方披露文件。保存公告页面及附件的原始 URL、报告名称、披露日期、下载日期、保存路径及 SHA-256，登记至 `manifest.json` 和证据台账。
3. **核对版本及截止日**：区分完整报告、摘要、更正或修订版本，保留已取得的原版及版本说明。核对相关更正、会计差错调整和追溯重述；如与待审文件使用的版本不同，列明差异及其原因，不静默择一。不能以最新一期报告替代所需历史期间，也不能用截止日之后发生的事实倒推此前结论。
4. **作为实质核对底稿**：逐项定位相关正文、表格、附注及其口径，核对上市公司财务数据、业务、股权及控制关系、关联事项、承诺履行等被披露的信息。区分合并与母公司、余额与发生额、年度与累计季度、审计与未经审计等口径；只核对报告实际覆盖的内容，不补齐报告未披露的事实。
5. **留存可复核证据**：对每个核对点记录待审文件原文位置及下载报告的章节、表名、原文摘录和已核验页码，关联来源及证据。存在差异时先排除期间、口径和版本差异，再按本 skill 的证据状态定性；仅完成下载不得声称已完成核对。
6. **如实处理取证失败**：某渠道不可用时尝试其他官方渠道；仍未取得对应报告或报告未公开、无法读取时，记录所需报告、已尝试渠道、具体原因及受影响事项，标记 `UNVERIFIABLE` 或相应覆盖状态。不得仅以“用户未提供”为由跳过，也不得编造下载成功或核对完成。

### 官方披露来源

| 来源 | 用途 |
|---|---|
| 巨潮资讯网 `cninfo.com.cn` | 上市公司公开年度报告、半年度报告、季度报告及更正公告 |
| 上交所 `sse.com.cn`、深交所 `szse.cn`、北交所 `bse.cn` | 对应上市公司的官方公告及报告附件 |
| 上市公司官网投资者关系页 | 公司正式披露的报告原文件；核对报告主体、期间及版本 |

检索仅使用上市公司名称、证券代码及公开报告名称等必要信息，不向外部服务上传待审申报文件或非公开底稿。

## 7. 同业核查勾稽（可选扩展）

### 触发条件

主文件出现"根据同业核查XXXX""据同业对比"等引用，或用户要求同业数据勾稽。

### 核查方式

1. 看同业范围文件（内部是否已传，或主文件是否自带同业清单）。
2. 主文件披露的这几个同业的数据（如各同业毛利率/市占率）→ 记录。
3. **外部搜索**这些同业对应指标 → 与主文件披露比对。
4. 外部真实数据 vs 主文件披露 → 勾稽。不符或主文件口径与同业范围文件不一致 → 标红，溯源到同业范围文件名+页码 或 外部URL。

### 同业数据源

| 来源 | 适用场景 |
|------|---------|
| 同业公司年报/招股书 | 上市公司同业 |
| 行业协会统计数据 | 行业整体数据 |
| 券商研究报告 | 行业分析数据（注意时效性） |
| Wind/同花顺行业数据 | 需用户有权限 |

### 注意事项

- 同业数据有**口径差异**（如毛利率计算方式、收入确认政策），核查时必须确认可比性；
- 同业数据有**时点差异**（年报 vs 最新季报），期间必须匹配；
- 主文件自带同业清单时，以主文件清单为准；无清单时，外部搜索同业务/同规模公司。

## 8. 来源评价统一入口

所有外部来源在写入问题清单前，先按 `source-evaluation.md` 完成：

- claim 类型判断；
- 来源层级和独立性评价；
- 直接内容页定位；
- 发布日期、访问日期和数据截止日记录；
- 反向证据检索；
- "没有找到证据"与"找到相反证据"区分；
- 来源更新后的透明修订记录。

工商、法规、案号、合规反向查证、年报和同业核查的具体工具路径仍按本文件执行；来源和证据字段统一写入 `evidence-ledger.json`。
