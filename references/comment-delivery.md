# Word 批注版交付规范（Excel 问题清单 + Word 批注版 + HTML 文件）

> 面向用户的交付物仅为三种：①**Excel 问题清单**（结构化问题、依据及续核闭环）；②**Word 批注版**（在**原件副本**上逐条插入批注）；③**HTML 文件**（结论、范围、核查依据、覆盖矩阵、限制及元审计结果）。内部 JSON/JSONL、证据包和续核表不另行交付，相关内容纳入 Excel 或 HTML。
> 批注版**绝不覆盖原件**：只读原件 → 另存副本 → 在副本上加批注。
> 本次新增批注及修订的作者统一为 **`Jasper AI`**。直接修改正文时开启修订模式，在新增 `w:ins`、`w:del` 等修订节点的 `w:author` 中使用 `Jasper AI`；保留原有批注及修订的作者，不覆盖原件。
> 文中数字与批注示例（如 169,066,761.70、148 条批注）来自历史项目实测，仅说明方法，不得当作当前任务事实。

## 一、批注体例（每条批注四段式）

```
【<类型标签>】<问题定性，含具体数字>
<证据/勾稽式>
<修订建议：请改为……>
<连带影响：同一表述在其他章节/其他文件亦有，需一并修改>
```

- **类型标签**：见 `references/error-taxonomy.md`。标签后可用"｜"补充限定（如`【数据错误｜与定稿附注不符】`）。
- **证据必须可复算**：写出勾稽式（如"利润总额183,158,040.36−所得税16,996,976.32=净利润166,161,064.04；归母136,466,284.39＋少数股东29,694,779.65=净利润，均勾稽一致，唯本行不符"）。
- **区分确认与疑似**：确认错误写"请改为…"；需核实的写"请核实…并以××为准"。
- **同时留痕正向结论**：已核对无误的可写`【勾稽-已复核无误】`；已修订的写`【已直接修订】`。批注版不只有问题，也有确认痕迹。

## 二、锚定范围（最小必要原则）

| 问题类型 | 锚定对象 |
|---|---|
| 单个数字错误 | **精确锚定到该数字所在的 Run**（如 `169,066,761.70`、`1,419.10`、`46,797.09`） |
| 句子/表述错误 | 锚定该句所在的 Run 或整段 |
| 表格单元格 | 锚定该单元格文本 |
| 整段/整表问题 | 锚定整段（避免锚定整个表格） |

> 锚定过宽（整章）会失去可操作性；锚定过窄（半个数字）会读不出上下文。以"读者一眼能看到出错处"为准。

## 三、实现（python-docx ≥ 1.2.0，已验证可用）

```python
from docx import Document

src = "原件.docx"; dst = "【复核批注版】原件.docx"
doc = Document(src)                      # 只读原件再另存

def iter_all_paragraphs(doc):
    """遍历正文 + 表格内的全部段落。
    ⚠️ 实测坑：doc.paragraphs 只返回 body 级段落，**不含表格单元格内的段落**；
    表格里的数字（如利润表“持续经营净利润 169,066,761.70”“非流动性资产处置损益 1,419.10”）
    若不遍历表格将全部锚定失败。"""
    for p in doc.paragraphs:
        yield p
    for t in doc.tables:
        for row in t.rows:
            for cell in row.cells:
                for p in cell.paragraphs:
                    yield p
                for nt in getattr(cell, "tables", []):   # 嵌套表格
                    for row2 in nt.rows:
                        for c2 in row2.cells:
                            for p2 in c2.paragraphs:
                                yield p2

def find_runs(doc, needle):
    """三级回退：①单 Run 精确命中 ②段落级（Run 被 Word 切碎）③表格段落级"""
    for p in iter_all_paragraphs(doc):
        for r in p.runs:
            if needle in r.text:
                return r
    for p in iter_all_paragraphs(doc):
        if needle in p.text:
            return p.runs                     # 传整个 runs 序列
    return None

# 2) 加批注（runs 可以是单个 Run，也可以是 Run 序列）
runs = find_run(doc, "169,066,761.70")
if runs is not None:
    doc.add_comment(
        runs,
        "【数据错误】备考利润表2026年1-6月“持续经营净利润”169,066,761.70元，"
        "而同表净利润166,161,064.04元（利润总额183,158,040.36−所得税16,996,976.32）、"
        "终止经营净利润为“-”。持续经营净利润应等于净利润，请核对备考审阅报告后更正。",
        author="Jasper AI", initials="JA")

doc.save(dst)                            # 另存，不覆盖原件
```

**要点与坑**
- Run 常被 Word 切碎（如 `169,066,` + `761.70`），精确匹配失败时退化为**段落级锚定**（传 `p.runs` 序列）。
- **表格内文字必须单独遍历**（`doc.tables → row.cells → cell.paragraphs`）：`doc.paragraphs` 不含表格段落，漏掉会导致财务报表类数字全部锚定失败（本项目实测：3 个锚点中 2 个在表格内，全部失败）。
- 若源文件**已存在批注**，`doc.add_comment()` 会追加而不覆盖：新增批注与既有批注并存，交付说明中应给出"新增条数"而非 `comments.xml` 总条数（本项目实测：原件已有 145 条既有批注，新增 3 条后总数为 148）。
- 锚定的 Run 序列必须是**非零长度的连续区间**；跨段落也支持。
- `add_comment` 的 `author` 统一使用 `Jasper AI`，便于筛选与回复；修订节点的 `w:author` 同样使用 `Jasper AI`。
- 用 `read_only` 方式打开原件，避免锁文件；输出文件名建议`【复核批注版】+ 原名`。

## 四、交付前门禁（逐条打勾，任一不过不得交付）

1. **本次新增**批注条数与 Excel 问题清单条数**一致**（逐条对应，编号可互查）；若原件已有既有批注，须按作者区分统计（新增数 ≠ comments.xml 总数）；
2. 每条批注的**锚定文本真实存在于原文**（用 `text/*.txt` 或重开 docx 校验）；
3. 每条批注含**类型标签 + 证据 + 修订建议**三要素；
4. 批注版**未覆盖原件**（原件 SHA256 与复核前一致）；
5. 交付说明中写明：原件路径、批注版路径、批注条数、作者名、生成时间；
6. 若某条无法精确锚定（如表格内文字被拆分），在 Excel 清单中注明"批注版锚定于整段"。

## 五、证据状态与批注措辞

每条批注必须同时带影响等级和证据状态。推荐格式：

```text
【FND-0001｜A级｜CONFIRMED｜数据错误】
<具体问题及原文>
<权威来源、公式或证据>
<最小修订建议>
<同一问题在其他文件/章节的连带影响>
```

措辞规则：

- `CONFIRMED`：请改为……；
- `CANDIDATE`：请核实……，当前为候选异常；
- `PASS`：已核对一致，记录检查范围和勾稽式；
- `UNVERIFIABLE`：本次无法核验，说明缺少的证据和已尝试来源；
- `NOT_IN_SCOPE`：本次未纳入范围，不写成通过。

批注数量、finding 数量、Excel 问题清单数量必须一致。批注锚点必须使用 [delivery-and-traceability.md](delivery-and-traceability.md) 规定的文件和章节定位，同时保留最小必要锚定。

交付数量和口径须与 Excel 及 HTML 一致；批注版路径、作者、新增条数和生成时间纳入 HTML 交付说明。
