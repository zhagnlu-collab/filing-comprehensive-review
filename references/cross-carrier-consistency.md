# 跨载体一致性核查

> 同一事实在申报文件里往往同时出现在**正文段落、表格、图、表下注释、目录**五类载体中。本文件规定这五类载体之间的交叉比对方法与高发场景。
> 只用同类载体互比（例如"段落 vs 段落"）会系统性漏掉"表已换版而图未同步""注释滞后于正文"这类问题。文中项目与数字均为脱敏示例。

## 1. 五类载体

| 载体 | 典型位置 | 常见被漏原因 |
|---|---|---|
| 正文段落 | 各章节叙述 | — |
| 表格 | 出资/股权结构表、财务数据表、承诺表 | — |
| **图** | 股权结构图、产权控制关系图、组织架构图、流程图、业务示意图 | **被当作"图片"整体排除，或只统计数量不消费内容** |
| 表下注释 | "注：…" | 只扫错别字，不做逻辑比对 |
| 目录 | 章节标题与页码 | 只在做格式检查时看 |

**铁律**：图是独立的数据载体，不是排版装饰。凡是标题或上文含"结构图／关系图／示意图／流程图／股权结构／产权控制关系／组织架构"的图，其列示的主体名称与数值必须与同节的表格、正文逐项比对。

## 2. 执行步骤

### 步骤 1：图的全量提取与定位

按文档顺序遍历 `word/document.xml` 的 body 子节点，逐段检查是否含 `w:drawing`／`a:blip`／`v:imagedata`，记录：

- 该图**前一个非空段落**的文本（用于判断这张图是什么图）；
- 该图所属章节；
- `r:embed` → `word/_rels/document.xml.rels` → `word/media/imageN.png` 的映射。

```python
W = 'http://schemas.openxmlformats.org/wordprocessingml/2006/main'
R = 'http://schemas.openxmlformats.org/officeDocument/2006/relationships'
A = 'http://schemas.openxmlformats.org/drawingml/2006/main'
V = 'urn:schemas-microsoft-com:vml'

def imgs_of(p_el):
    """返回该段落内嵌图片的 rId 列表（DrawingML 与 VML 两种写法都要覆盖）"""
    rids = []
    for blip in p_el.iter('{%s}blip' % A):
        rid = blip.get('{%s}embed' % R)
        if rid:
            rids.append(rid)
    for im in p_el.iter('{%s}imagedata' % V):
        rid = im.get('{%s}id' % R)
        if rid:
            rids.append(rid)
    return rids
```

**注意**：解析管线若只产出 `kind='p'` 和 `kind='table'` 两类 block，就是结构性失明。必须在解析阶段就产出 `kind='image'`，否则后续任何检查都无法发现图的存在。仅统计出 `images=16` 而不消费其内容，等于没做。

### 步骤 2：图的识读

- 用 `PIL` 裁切并放大（长图按上/中/下分段，关键区域放大 2–4 倍）后逐张识读；
- 记录图中每个主体的**名称**与**数值**，写入事实台账，来源标注为"文件名 + 图 + 所属小节"；
- 图中层级多于表格时（如穿透到上层股东的股东），把上层数据也记入台账并**单独核验**。

### 步骤 3：交叉比对矩阵

对每一个"主体—数值"对，填一张矩阵：

| 主体 | 正文段落 | 表格 | 图 | 表下注释 | 目录 | 是否一致 |
|---|---|---|---|---|---|---|

任一格与其他格不一致 → 出一条 finding。**不得只填同类载体的列。**

### 步骤 4：外部回源（涉及非上市主体时）

股权结构、合伙人、注册资本、名称属于**转抄工商登记**的数据，抄录错误率高，必须回工商登记源核验：

1. 优先用企查查等工商核查工具（国家企业信用信息公示系统，T+0）取一层股东/合伙人、出资比例、认缴出资额、注册资本；
2. **必须同时调取变更记录**（`get_change_records`）。名称沿革、比例变化、注册资本增减**只有变更记录才能定性**；
3. 一层比例只按工具返回逐字引用，**不得相乘推断穿透比例**。

## 3. 高发场景清单

按本清单逐项过一遍，命中即出问题：

1. **表已换版、图未同步**——表格被替换（含以修订方式删除旧表、插入新表）而结构图仍是旧版。判定方法：把图中的比例与**被删除的旧表**比对，若逐项吻合即可确认。
2. **图内层级遗漏主体**——图只画了主要股东，遗漏了合计不为 100% 的那部分。逐层验算：每层各主体比例之和应等于 100.00%（±0.01 为舍入尾差）；不足即遗漏。
3. **图内数值笔误**——如把 69.99% 写成 69.00%。同样表现为该层合计不足。
4. **表下注释滞后**——注释说明的是更名/迁址的**前一阶段**，而表格已用最新名称；或注释与表格名称不一致。
5. **主体名称三方不一致**——图用旧名、表用新名、注释说第三次更名，三个口径并存。以工商变更记录的**最新登记名称**为权威。
6. **出资表合计与同节注册资本不符**——"合计"应等于注册资本（或出资总额）。不等即须追因：是遗漏出资人、是增资前后口径混用，还是抄录错误。**不得降为尾差。**
7. **图与表口径期次不同**——表用增资后口径、图用增资前口径（或反之）。用工商变更记录中的**注册资本变更日期**与**金额**对齐期次。
8. **目录 vs 正文 vs 图标题**——图标题所在的章节号与目录不一致。
9. **正文口径与图不一致**——如正文写"收购 100% 股权"而图/表按"取得不低于 X%"画。
10. **表内合计与明细加总不符**——先排除舍入尾差；**已识别为"超出常规尾差"的必须升级追因**，不得留在 C 级。

## 4. 定级建议

| 情形 | 建议等级 |
|---|---|
| 图与表的核心比例不一致 | A（图或表之一必然错误，须确定权威口径后重绘/重编） |
| 图内遗漏主体致该层合计不足 100% | A |
| 出资表合计 ≠ 同节注册资本 | A 或 B（须先追因，不得降为尾差） |
| 图/表/注释主体名称口径不一致 | B |
| 图内数值笔误但不影响合计 | B |
| 图标题编号与目录不一致 | C |

## 5. 交付要求

1. **归档图证据**：把出问题的结构图原图（必要时含放大裁切件）复制到交付目录的证据子目录，命名体现"主体 + 图中载明的数值"，便于项目组直接在 Word 原件中定位复核。
2. **写明口径沿革**：凡涉及名称、比例、注册资本沿革的 finding，必须列出**工商变更记录的时间轴**（日期 + 变更前 → 变更后），否则项目组无法判断哪一版才是现行口径。
3. **不静默择一**：图与表冲突时，列明双方数值、差额、来源与期间，说明需由谁确认权威口径，**不得自行判定"图错"或"表错"**。
4. **覆盖矩阵入交付**：交付说明中列出五类载体各自的覆盖状态，避免"问题条数很多"掩盖"某一类载体零覆盖"。

## 6. 反面教训（脱敏）

某重组项目复核中，一次"全面复核"交付了数十条问题，覆盖了正文、表格、目录、法规引用和算术勾稽，但**图片整体未纳入口径**，理由写在交付限制栏里（"图片未纳入正文口径"）。该文件中恰好有十余张承载关键比例的结构图。次轮换版后，表格被整体替换为新版口径而结构图未同步，形成图与表比例、主体名称均不一致的问题，直到用户单独点名追问才被发现。

两个可复用的结论：

- **把"做不到"写进限制栏，不等于完成了交付**。限制必须先做闭环判断：是否影响结论可靠性、能否本轮消除。能消除而未消除的，是未执行，不是限制。
- **问题条数不构成覆盖完整性的证明**。应按载体拆开看覆盖矩阵——数量上的完整感最容易掩盖载体上的结构性盲区。
